## 第一章：认识你的电脑（文件、路径、环境变量与常用软件）

| 平台 | 报错现象 | 常见原因 | 排查与解决 | 官方参考链接 |
|---|---|---|---|---|
| 通用 | 修改环境变量后不生效 | 已打开的程序/窗口不会自动刷新 | 重启终端窗口或程序后再验证 | [环境变量](https://learn.microsoft.com/zh-cn/windows/win32/procthread/environment-variables) |
| Windows | `echo %变量%` 原样显示 | 终端类型不对或变量不存在 | cmd 用 `%名%`，PowerShell 用 `$env:名` | 同上 |
| Windows | `'xxx' 不是内部或外部命令`（cmd）/ `无法将"xxx"项识别为 cmdlet`（PowerShell） | 目录不在 PATH，或加了 PATH 没重启终端 | 加入 Path 后**重启**终端；核对路径拼写与目录是否存在 | [文件路径](../第一册-基础/第一章-Windows入门/文件路径.md) |
| Windows | `setx` 提示无效语法/参数过多 | 值里含空格未加引号 | 用双引号括起来：`setx 变量名 "含空格的值"` | [setx](https://learn.microsoft.com/zh-cn/windows-server/administration/windows-commands/setx) |
| Windows | setx 后当前窗口不生效 | setx 只对将来的窗口生效 | 新开命令行窗口验证 | 同上 |
| Windows | setx 修改 PATH 后系统命令大面积失效 | 用 `%Path%` 回写被截断到 1024 字符，覆盖了系统 Path | 图形界面恢复完整 Path；勿用 `%Path%` 整体回写 setx | 同上 |
| Windows | 编辑系统变量时拒绝访问 | 系统变量需要管理员权限 | 用管理员账户操作 | [Windows 文件管理系统](../第一册-基础/第一章-Windows入门/Windows-文件管理系统.md) |
| Windows | 用"编辑文本"整行改 Path 后原有命令全失效 | 误删条目或分号 | 改用「新建/编辑」逐条添加；至少保留 `%SystemRoot%\system32` | [文件路径](../第一册-基础/第一章-Windows入门/文件路径.md) |
| 通用 | 路径已在 PATH 里，程序仍找不到 | 加的是上一层目录，或目录不存在 | 找到可执行文件所在目录再加进去 | 同上 |
| Windows | 用户变量对服务/其他账户不可见 | 用户变量只对当前账户生效 | 需要全局生效时加到系统变量 | [Windows 文件管理系统](../第一册-基础/第一章-Windows入门/Windows-文件管理系统.md) |
| macOS | `zsh: command not found: xxx` | 程序目录不在 PATH，或改完 `~/.zshrc` 没重开终端 | `echo $PATH` 检查；写入 `~/.zshrc` 后 `source ~/.zshrc` 或重开终端 | [文件路径（macOS 版）](../第一册-基础/第一章-Windows入门/文件路径-macOS.md) |
| macOS | 写入 `~/.zshrc` 后新终端仍不生效 | 写错文件（如 `.bash_profile`），或误用 `>` 覆盖 | 确认写入 `~/.zshrc` 且用 `>>` 追加；`source ~/.zshrc` 验证 | [文件管理系统-macOS](../第一册-基础/第一章-Windows入门/文件管理系统-macOS.md) |
| macOS | 双击打开的图形界面程序读不到新环境变量 | 图形界面程序不读取 `~/.zshrc` | 重启该程序；或在终端里用 `open` 启动 | 同上 |
| macOS | `Operation not permitted` / `Permission denied` | 权限不足，或目标是受系统保护的位置 | 先确认是否需要 `sudo`，不要强行提权；检查访达「显示简介 → 共享与权限」 | [macOS 文件管理系统](../第一册-基础/第一章-Windows入门/文件管理系统-macOS.md) |
| Windows | WSL 终端里 `code` 不可用 | 安装时未勾选 Add to PATH | 重装勾选或手动加 PATH | [软件安装-VSCode](../第一册-基础/第一章-Windows入门/软件安装-VSCode.md) |
| macOS | macOS 终端里 `code` 不可用 | 未运行 "Install 'code' command in PATH" | 命令面板（`Cmd+Shift+P`）运行该命令后重启终端 | 同上 |
| 通用 | Markdown 表格/任务列表预览不显示 | VS Code 预览遵循 CommonMark，表格是 GFM 扩展 | 以 GitHub 渲染为准 | [CommonMark](https://spec.commonmark.org/) |

## 第三章：照着教程报错（四查清单）

| 检查项 | 问自己 | 处理 |
|---|---|---|
| 版本匹配 | 教程发布时间？版本与我一致吗？ | 对照官方文档当前写法 |
| 命令安全 | 每条命令看得懂吗？含 `sudo`、`curl \| bash`、`rm`？ | 弄懂再执行，不理解不执行 |
| 结果验证 | 教程说成功就算成功？ | 用验证命令自查，以结果为准 |
| 来源核实 | 域名是官方吗？ | 官方优先，社区多篇对照 |

| 平台 | 报错现象 | 常见原因 | 排查与解决 | 官方参考链接 |
|---|---|---|---|---|
| 通用 | 教程里的命令报"找不到" | 教程过时或软件未装 | 先核对版本，再查对应章节的「常见报错检查」 | [甄别实战](../第一册-基础/第三章-网络教程的可信度/甄别实战-判断一个教程.md) |
| 通用 | 页面打不开 / 下载很慢 | 网络问题，或域名并非官方 | 检查网络与代理；核实域名后换官方镜像 | 同上 |
| 通用 | 复制粘贴后结果和教程不一样 | 缺少前置步骤或版本不同 | 回到教程开头按顺序重来，对照官方文档 | 同上 |

## 第四章：终端与开发环境

| 平台 | 报错信息 | 常见原因 | 排查与解决 | 官方参考链接 |
|---|---|---|---|---|
| Windows | `0x80370102`（请启用虚拟机平台） | 未启用虚拟机平台或 BIOS 虚拟化关闭 | `dism.exe ... /featurename:VirtualMachinePlatform` 启用后重启；BIOS 开 VT-x/AMD-V | [WSL 排障](https://learn.microsoft.com/zh-cn/windows/wsl/troubleshooting) |
| Windows | `0x80070003` 安装失败 | 发行版装在非系统盘 | 新内容保存位置改回 C 盘 | 同上 |
| Windows | `0x800701bc`（需要更新内核） | WSL 内核过旧 | `wsl --update` | 同上 |
| Windows | `wsl --install` 卡在 0.0% | 商店下载失败 | `wsl --install --web-download -d Ubuntu` | [WSL 安装](https://learn.microsoft.com/zh-cn/windows/wsl/install) |
| Windows | `E: Unable to locate package` | 索引未更新或源不可达 | `sudo apt update`；换国内镜像 | [Ubuntu 包管理](https://ubuntu.com/server/docs/how-to/software/package-management/) |
| 通用 | 更新/下载速度极慢 | 官方源在境外 | Windows：换 apt/conda 国内镜像；macOS：参考 Homebrew 镜像配置 | [Homebrew Installation](https://docs.brew.sh/Installation) |
| 通用 | `curl: Failed to connect to ... port 443` / `Could not resolve host` | 网络不通或 DNS 故障 | `ping 域名` 排查；检查 VPN/代理 | [WSL 排障](https://learn.microsoft.com/zh-cn/windows/wsl/troubleshooting) |
| 通用 | `SSL certificate verify failed`（curl/wget） | 系统证书过期或代理拦截 | Windows/WSL：`sudo apt install ca-certificates`；macOS：`brew install ca-certificates` | [conda 排障](https://docs.conda.io/projects/conda/en/latest/user-guide/troubleshooting.html) |
| macOS | `zsh: command not found: brew` | 安装后未把 brew 加入 PATH | 按提示把 `eval "$(/opt/homebrew/bin/brew shellenv)"` 写入 `~/.zprofile` 并重开终端 | [终端与 Homebrew](../第一册-基础/第四章-WSL与开发环境搭建/终端与Homebrew-macOS.md) |
| macOS | Homebrew 安装/更新卡住、`Failed to connect to github.com` | 官方源在境外 | 检查网络/代理；参考官方 Installation 的镜像配置 | [Homebrew Troubleshooting](https://docs.brew.sh/Troubleshooting) |
| macOS | `xcrun: error: invalid active developer path` / `git: command not found` | 缺少 Xcode 命令行工具 | 运行 `xcode-select --install` 按提示安装 | [Homebrew Installation](https://docs.brew.sh/Installation) |
| macOS | `Permission denied` / `Operation not permitted`（装软件时） | 权限不足或系统保护 | 不要强行提权；优先安装到用户目录（如 `~/miniforge3`） | [Python 环境配置（macOS 版）](../第一册-基础/第四章-WSL与开发环境搭建/Python-环境配置-macOS.md) |
| Windows | `command not found: mamba` 或 `command not found: conda` | mamba/conda 未初始化 | `source ~/.bashrc` 或重装选 yes | [Miniforge](https://github.com/conda-forge/miniforge/releases) |
| macOS | `command not found: mamba` 或 `command not found: conda` | 初始化写入 `~/.zshrc` 但当前窗口未刷新 | `source ~/.zshrc`；或 `~/miniforge3/bin/conda init zsh` 后重开终端 | [Python 环境配置（macOS 版）](../第一册-基础/第四章-WSL与开发环境搭建/Python-环境配置-macOS.md) |
| 通用 | `PackagesNotFoundError` | 包名拼错或不在渠道 | `mamba search` 核对；`-c conda-forge` | [管理渠道](https://docs.conda.io/projects/conda/en/latest/user-guide/tasks/manage-channels.html) |
| 通用 | `CondaHTTPError: HTTP 000` | 网络连不上官方源 | 配置清华镜像；检查代理 | [conda 排障](https://docs.conda.io/projects/conda/en/latest/user-guide/troubleshooting.html) |
| macOS | Miniforge 与 Homebrew 相互干扰 | 用 Homebrew 安装了 Miniforge（官方不推荐） | 卸载 Homebrew 版，按官方脚本重装 | [Miniforge 官方仓库](https://github.com/conda-forge/miniforge) |

| 通用 | 回复中断 / 提示上下文不够 | 上下文窗口被占满 | 开新会话；减少 MCP 工具与文件上下文 | [Agents](https://opencode.ai/docs/agents/) |

| 通用 | `E325: ATTENTION`（交换文件 `.xxx.swp`） | 崩溃/断连留下交换文件，或文件已在另一窗口打开 | 确认后删除 `.swp`；恢复内容用 `vim -r 文件名` | [崩溃恢复](https://vimhelp.org/usr_11.txt.html#ATTENTION) |
| 通用 | `E45: 'readonly' option is set` | 文件只读或无写权限 | 用 `sudo vim 文件`；或执行 `:w !sudo tee %` | [E45](https://vimhelp.org/message.txt.html#E45) |
| 通用 | `E37: No write since last change` | 有未保存修改却执行 `:q` | 要保存用 `:wq`；不要就 `:q!` | [E37](https://vimhelp.org/message.txt.html#E37) |
| 通用 | `E212: Can't open file for writing` | 目录不存在或无写权限 | 核对路径；系统目录用 `sudo vim` | [E212](https://vimhelp.org/message.txt.html#E212) |
| 通用 | 按键"打不出字"或行为奇怪 | 不在正确的模式 | 先按 `Esc` 回普通模式 | [Vim 入门](../第二册-进阶/第七章-Vim/Vim-入门.md) |
| 通用 | 粘贴代码时缩进乱掉 | 自动缩进与终端粘贴冲突 | `:set paste` 后再粘贴，完后 `:set nopaste` | [:set paste](https://vimhelp.org/options.txt.html#%27paste%27) |
| Windows | 方向键打出 `A` `B` `C` `D` | WSL/Ubuntu 的精简版或兼容模式 | 安装完整版 `sudo apt install vim`；或先用 `hjkl` | [Vim 官方文档](https://www.vim.org/docs.php) |
| 通用 | 中文显示乱码 | 编码不是 UTF-8 或识别错误 | `:set encoding=utf-8`；文件编码不对用 `:e ++enc=utf-8` 重开 | [:set encoding](https://vimhelp.org/options.txt.html#%27encoding%27) |
| 通用 | 误删 / 改坏内容 | 误操作 | `u` 撤销、`Ctrl + r` 重做；崩溃后 `vim -r 文件名` 恢复 | [撤销 undo](https://vimhelp.org/undo.txt.html) |
