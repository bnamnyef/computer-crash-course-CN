# 常见报错检查：第一章 认识你的电脑

> 本章正文遇到报错时的快速排查表。详细原理与操作见各篇正文；全部章节的汇总见[附录《常见报错速查表》](../../附录-速查总览/常见报错速查表.md)。
>
> 「平台」列说明：`通用` = 两个平台都会遇到；`Windows` / `macOS` = 该平台专有（含命令写法差异）。

## 一、环境变量与 PATH（本章重点）

| 平台 | 报错现象 | 常见原因 | 排查与解决 | 参考 |
|---|---|---|---|---|
| 通用 | 修改环境变量后 `echo` 还是旧值 | 已打开的程序/窗口不会自动刷新 | 重启终端窗口或程序后再验证 | [环境变量 - Microsoft Learn](https://learn.microsoft.com/zh-cn/windows/win32/procthread/environment-variables) |
| Windows | `echo %变量名%` 原样显示 | 终端类型不对或变量不存在 | cmd 用 `%名%`，PowerShell 用 `$env:名`；核对变量名拼写 | [Windows 文件管理系统](./Windows-文件管理系统.md) |
| Windows | cmd 提示 `'xxx' 不是内部或外部命令，也不是可运行的程序或批处理文件` | 程序目录不在 PATH，或加了 PATH 没重启终端 | ①确认目录已加入「Path」；②**重启**命令行窗口；③核对路径拼写与目录是否存在 | [文件路径](./文件路径.md) |
| Windows | PowerShell 提示 `无法将“xxx”项识别为 cmdlet、函数、脚本文件或可运行程序的名称` | 同上（PowerShell 版的同一种报错） | 处理方式与上一条相同 | 同上 |
| Windows | `setx` 提示错误：无效语法 / 参数过多 | 值里含空格却没有加引号 | 把值用双引号括起来：`setx 变量名 "含空格的值"` | [setx - Microsoft Learn](https://learn.microsoft.com/zh-cn/windows-server/administration/windows-commands/setx) |
| Windows | setx 后**当前窗口**仍找不到新命令 | setx 只对将来的窗口生效 | 关闭并重新打开命令行窗口，不要用旧窗口验证 | 同上 |
| Windows | setx 修改 PATH 后，`ipconfig`、`regedit` 等系统命令大面积失效 | 用 `setx Path "%Path%;新目录"` 时，`%Path%` 只展开当前窗口的值且**被截断到 1024 字符**，把系统 Path 覆盖坏了 | 立即用图形界面（系统属性 → 环境变量）恢复完整 Path；不要用 `%Path%` 整体回写 setx | 同上 |
| Windows | 图形界面编辑 Path 时提示拒绝访问/按钮不可用 | 系统变量需要管理员权限 | 用管理员账户操作，或右键"以管理员身份运行"设置入口 | [Windows 文件管理系统](./Windows-文件管理系统.md) |
| Windows | 用"编辑文本"整行改 Path 后原有命令全失效 | 误删了原有条目或分号 | 改用「新建/编辑」逐条添加；如已破坏，对照另一台电脑恢复默认值（至少保留 `%SystemRoot%\system32`） | [文件路径](./文件路径.md) |
| 通用 | 路径已在 PATH 里，程序仍找不到 | 加的是上一层目录，不是含可执行文件的目录；或目录不存在 | 找到可执行文件所在的具体目录，把它加进去 | 同上 |
| Windows | 某些后台服务/其他账户运行的程序找不到你装的命令 | 用户变量只对当前账户生效 | 需要全局生效时，把变量加到**系统变量** | [Windows 文件管理系统](./Windows-文件管理系统.md) |
| macOS | `zsh: command not found: xxx` | 程序目录不在 PATH，或改完 `~/.zshrc` 没重开终端 | `echo $PATH` 检查；把目录写进 `~/.zshrc` 后 `source ~/.zshrc` 或重开终端 | [文件路径（macOS 版）](./文件路径-macOS.md) |
| macOS | 写入 `~/.zshrc` 后新终端仍不生效 | 写错了文件（如写进 `.bash_profile`），或误用 `>` 覆盖了配置 | 确认写入的是 `~/.zshrc` 且用 `>>` 追加；`source ~/.zshrc` 验证 | [文件管理系统-macOS](./文件管理系统-macOS.md) |
| macOS | 双击打开的图形界面程序读不到新环境变量 | 图形界面程序不读取 `~/.zshrc` | 重启该程序；或在终端里用 `open` 启动 | [文件管理系统-macOS](./文件管理系统-macOS.md) |
| macOS | `Operation not permitted` / `Permission denied` | 权限不足，或目标是受系统保护的位置 | 先确认是否真的需要 `sudo`，不要对系统目录强行提权；必要时在访达「显示简介 → 共享与权限」中检查 | [macOS 文件管理系统](./文件管理系统-macOS.md) |

## 二、VS Code 与 Markdown

| 平台 | 报错现象 | 常见原因 | 排查与解决 | 参考 |
|---|---|---|---|---|
| Windows | WSL 终端里 `code` 命令不可用 | 安装 VS Code 时未勾选 Add to PATH | 重装并勾选，或手动把 VS Code 目录加入 PATH | [软件安装-VSCode](./软件安装-VSCode.md) |
| macOS | macOS 终端里 `code` 命令不可用 | 未运行 "Install 'code' command in PATH" | 在 VS Code 命令面板（`Cmd+Shift+P`）运行该命令，然后重启终端 | [软件安装-VSCode](./软件安装-VSCode.md) |
| 通用 | Markdown 表格/任务列表预览不显示 | VS Code 预览遵循 CommonMark，表格等是 GFM 扩展语法 | 表格与任务列表以 GitHub 渲染为准 | [Markdown 使用与 VS Code 插件](./Markdown-使用与VS-Code插件.md) |
