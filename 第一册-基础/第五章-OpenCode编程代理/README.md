# 第五章导读：先认识 AI 编程代理，再开始动手

> 前一章你已经装好了 WSL 与 Python 环境，这一章给终端配一个「AI 程序员」——OpenCode。它能在你的项目里读代码、改文件、运行命令，把「问 AI」升级成「让 AI 动手」。先混个脸熟，再照着路线图动手。

## 一、为什么要学这一章？

- **AI 编程代理是当下最实用的效率工具**：它能理解整个项目、直接修改代码、执行命令并验证结果，而不只是被动回答你的问题；
- **后续章节要用到它**：第六章 Git 会给出让 OpenCode 帮你操作 Git 的提示词，先在本章把它装好、配置好，后面直接用；
- **门槛比想象中低**：安装一条命令，配置一次 API 密钥，之后用中文对话即可，不需要你懂编程。

## 二、名词铺垫（先混个脸熟，不用背）

| 名词 | 一句话解释 | 生活比喻 |
|---|---|---|
| 编程代理 / Coding Agent | 能自主读代码、改代码、运行命令的 AI 程序 | 会自己动手的 AI 助手 |
| 终端界面 / TUI | 只在终端里运行的文字界面 | 全键盘操作的「驾驶舱」 |
| 提供商 / Provider | 提供 AI 模型的服务厂商，如 OpenAI、DeepSeek | 发电厂 |
| API 密钥 / API Key | 调用模型服务时的身份凭证 | 会员卡密码 |
| 模型 / Model | 负责思考和生成内容的 AI 程序 | 你雇的那位「工程师」 |
| 上下文窗口 | 模型单次对话能处理的信息量上限 | 一次能看完多少资料 |
| Plan 模式 | 只输出方案、不改代码的工作模式 | 先看图纸再施工 |
| Build 模式 | 按方案动手改代码的默认模式 | 正式施工 |
| 撤销 / Undo | 把上一步不满意的改动回退掉 | 游戏里的「读档」 |
| MCP | 让 OpenCode 接入数据库、GitHub 等外部工具的标准接口 | 给 AI 配的「通用插口」 |

> API 密钥、提供商等概念在第二章已经讲过；本章只讲怎么把它们填进 OpenCode。

## 四、学习建议

1. **小步试水**：先拿一个测试项目练手，用 Plan 模式让它出方案，满意后再切 Build 模式动手；不满意随时 `/undo`。
2. **Key 是密码**：API 密钥不要写进代码、发到聊天或提交到仓库，泄露立即到平台吊销重发。
3. **它是助手不是替身**：生成的代码和命令仍需你过目、确认、验证；不可逆命令（如删除、推送）放行前务必看清。
