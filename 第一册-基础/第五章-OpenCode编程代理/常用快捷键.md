# 常用快捷键：第五章 OpenCode

> OpenCode 在终端里运行，几乎所有操作都能用键盘完成。下表为官方 Keybinds 文档中的默认键位，可在 `tui.json` 中自定义。全书的汇总见[附录《常用快捷键汇总表》](../../附录-速查总览/常用快捷键汇总表.md)。

## 一、对话与输入

| 快捷键 | 作用 |
|---|---|
| `Enter` | 发送消息 |
| `Shift + Enter` / `Ctrl + J` | 输入换行（不发送） |
| `Esc` | 中断正在生成的回复 |
| `Page Up` / `Page Down` | 翻阅长回复 |
| `↑` / `↓` | 翻看历史输入 |
| `Ctrl + V` | 粘贴 |

## 二、模式与命令

| 快捷键 | 作用 |
|---|---|
| `Tab` / `Shift + Tab` | 切换代理模式（Build / Plan） |
| `Ctrl + P` | 打开命令列表 |
| `/` 开头输入 | 执行斜杠命令，如 `/init`、`/connect`、`/models`、`/undo` |

## 三、Leader（前导键）组合

OpenCode 用 **Leader 键**（默认 `Ctrl + X`）承载大部分功能键，避免与终端冲突：先按 `Ctrl + X`，松开后再按下一个键。

| 快捷键 | 作用 |
|---|---|
| `Ctrl + X` 然后 `N` | 新建会话 |
| `Ctrl + X` 然后 `L` | 查看会话列表 |
| `Ctrl + X` 然后 `M` | 选择模型 |
| `Ctrl + X` 然后 `A` | 切换代理（Build / Plan 等） |
| `Ctrl + X` 然后 `U` | 撤销上一处修改 |
| `Ctrl + X` 然后 `R` | 重做被撤销的修改 |
| `Ctrl + X` 然后 `E` | 用外部编辑器编辑输入 |
| `Ctrl + X` 然后 `Q` | 退出 OpenCode |

> 表中「用外部编辑器编辑输入」用的是环境变量 `EDITOR` 指定的编辑器。把它设置为 `vim` 后，即可按 `Ctrl + X` 然后 `E`（或 `/editor`）在 Vim 里写长消息；配置步骤见[《安装 OpenCode》第七节](./在WSL内安装OpenCode.md)，Vim 基础见选修[《Vim 入门》](../../第二册-进阶/第七章-Vim/Vim-入门.md)。

## 四、输入框编辑（Emacs / Readline 风格）

| 快捷键 | 作用 |
|---|---|
| `Ctrl + A` / `Ctrl + E` | 光标跳到行首 / 行尾 |
| `Ctrl + U` / `Ctrl + K` | 删除光标前 / 光标后的内容 |
| `Ctrl + W` | 删除前一个单词 |
| `Alt + B` / `Alt + F` | 光标按单词前移 / 后移 |

## 五、与 VS Code 快捷键冲突怎么办

在 VS Code 的集成终端里运行 OpenCode 时，部分按键会先被 VS Code 拦走，传不到 OpenCode——典型的就是 `Ctrl + P`：VS Code 会拿它去打开「快速打开」文件搜索。解决办法有两种。

**方法一：把对应功能加入排除项（逐个微调）**

1. 点左下角齿轮 → 设置；
2. 搜索 `terminal.integrated.commandsToSkipShell`；
3. 在列表里添加 `-workbench.action.quickOpen`，VS Code 就不再拦截 `Ctrl + P`，而是把它交给终端里的 OpenCode。

```json
"terminal.integrated.commandsToSkipShell": [
  "-workbench.action.quickOpen"
]
```

> 其他冲突按键同理：在「键盘快捷方式」里查到功能对应的命令 ID，用 `-命令ID` 的形式加进这个列表，一次解决一个。

**方法二：一刀切**

在设置里搜索并勾选 `terminal.integrated.sendKeybindingsToShell`：把绝大多数快捷键都优先发给终端（OpenCode），VS Code 不再拦截。缺点是 VS Code 终端自身的快捷键也会受影响（例如 `Ctrl + F` 查找会失效），适合冲突较多、希望 OpenCode 完全接管键盘的情况。
