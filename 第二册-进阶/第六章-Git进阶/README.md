# 第六章导读：先认识版本控制，再开始 Git

> 第二册进阶的第一章：用 Git 给代码（和任何文本文件）装上"时光机 + 保险柜"。先混个脸熟，再动手，二十分钟就能跑通基本流程。

## 一、为什么要学这一章？

- Git 是当前最通用的版本控制工具，几乎所有开源项目和公司都在用——学会它是从"写代码"到"正规开发"的分水岭；
- 它解决的痛点非常实在：改坏了能回退、改了什么一目了然、项目能备份到 GitHub 不怕丢；
- 配合第五章装的 OpenCode，你还能让 AI 帮你操作 Git，本章给出可直接复制的提示词。

## 二、名词铺垫（先混个脸熟，不用背）

| 名词 | 一句话解释 | 生活比喻 |
|---|---|---|
| 版本控制 | 记录文件每次改动、支持回退与协作的系统 | 游戏的"存档/读档" |
| 仓库（Repository） | 项目 + 它的全部历史记录 | 项目"档案柜" |
| 提交（Commit） | 一次改动拍下的快照 | 存一个档 |
| 暂存区 | 提交前临时存放改动的区域 | 提交前的"待办筐" |
| 分支（Branch） | 独立的开发线，互不干扰 | 平行世界 |
| 合并（Merge） | 把一个分支的改动合入另一个 | 把平行世界合回来 |
| 远程仓库 | 托管在 GitHub 等服务器上的仓库 | 云备份柜 |

## 四、学习建议

1. **建个测试仓库练手**：随便建个文件夹 `git init` 反复练习 add/commit/回退，练坏了删掉重来，零成本。
2. **GitHub 一节可跳过**：只想本地记录历史的话，进阶篇第二节可以晚点再看。
3. **提交信息写人话**：commit 信息是写给未来的自己看的，说明"改了什么"，而不是"改了文件"。
